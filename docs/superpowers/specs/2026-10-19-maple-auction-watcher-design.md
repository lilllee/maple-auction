# 메이플 옥션 매물 감시기 — 설계

작성일: 2026-10-19
상태: 초안 (사용자 승인 대기)

## 1. 의도

메이플스토리 PC 옥션(https://auction.maplestory.nexon.com)에서 사용자가 정해 둔 조건의 아이템을
근무 시간 동안 자동으로 반복 검색하고, 가격이 가장 싼 상위 3건이 바뀌면 카카오톡으로 알려주는
개인용 프로그램이다.

왜 필요한가:

- 원하는 매물이 올라왔는지 보려고 15분마다 직접 옥션에 들어가 검색하는 일이 번거롭다.
- 옥션 검색은 하루 100회로 제한되어 있어 아껴 써야 한다. 프로그램이 대신 일정하게 검색하고, 사용자는
  알림을 보고 살 때만 들어간다.

## 2. 사용자가 정한 것

- 검색 조건은 조건검색 탭과 같은 항목으로 지정한다. 첫 번째 대상은 다음과 같다.
  - 아이템명: 에테르넬 나이트헬름
  - 잠재등급: 레전드리
  - 잠재능력: "합산" 모드, 스킬 재사용 대기시간 감소 2 이상, STR %증가 9 이상
- 15분마다 한 번 검색한다.
- 결과를 가격 낮은 순으로 정렬해 상위 3건의 가격과 아이템 상세를 보낸다.
- 알림 수단은 카카오톡이며 받는 사람은 본인이다.
- 검색 조건은 프로그램 실행 전에 `.env`에 적어 두고, 실행 중에는 바꾸지 않는다.
- 알림은 상위 3건이 바뀌었을 때만 보낸다. 같은 결과면 보내지 않는다.
- 회사에서 근무 시간에만 켜 두고 퇴근할 때 끈다. 구매는 프로그램을 끈 뒤 직접 들어가서 한다.
- 프로그램은 회사 Windows PC에서 돌린다. 브라우저 창은 근무 시간 내내 최소화한 채 띄워 둬도 된다.
- 자동 구매는 하지 않는다.

## 3. 목표, 비목표, 안티목표

목표:

- `.env` 조건으로 주기마다 검색해 상위 N건(기본 3)을 뽑고, 바뀌었을 때만 카카오톡으로 보낸다.
- 하루 검색 한도를 프로그램이 스스로 확인하고 존중한다.
- 로그인은 사람이 브라우저에서 한 번만 한다. 그 세션을 프로그램이 이어서 쓴다.
- 세션이 끊기면 사용자에게 알리고 다시 로그인할 수 있게 한다.

비목표 (이번에는 하지 않음):

- 자동 구매, 구매 희망가 등록, 판매.
- 여러 아이템 조건을 동시에 감시하는 것. 이번 버전은 조건 1개만 다룬다.
- 서버나 클라우드에서 24시간 돌리는 것. 근무 시간 동안 사용자 PC에서만 돈다.
- 친구에게 보내기, 단체방 알림.
- 웹 UI나 대시보드.

안티목표 (동작해도 이러면 실패):

- 하루 검색 한도를 프로그램이 다 써 버려서 사용자가 직접 검색을 못 하게 되는 것.
- 같은 내용의 알림이 반복되어 알림이 소음이 되는 것.
- 넥슨 계정 비밀번호나 OTP를 프로그램이 저장하거나 입력하는 것.
- 사용자가 모르는 사이에 세션이 끊겨서 하루 종일 아무 알림도 안 오는 것. 끊기면 반드시 알려야 한다.

## 4. 제약과 조사 결과

### 4.1 넥슨 옥션 API (번들 분석으로 확인)

옥션 웹은 Vite 기반 SPA이고, 모든 데이터는 `https://api.mskr.nexon.com` 의 JSON API로 가져온다.
HTML을 긁을 필요가 없다. 번들에서 확인한 내용은 다음과 같다. 정확한 응답 형태는 구현 단계에서
실제 요청을 보고 확정한다.

- 인증: 넥슨 로그인 쿠키 기반 (`withCredentials: true`). 페이지 로드 시 `POST /v1/auth/web-token/session`
  으로 웹 토큰 세션을 만든다. OTP 미연동 계정, 그린메이플ID 미등록 계정은 거부된다.
- 단일 세션: 다른 환경에서 접속이 감지되면 기존 세션이 401(`WEB_TOKEN_REQUIRED`)로 끊긴다.
  426 응답은 로그인 페이지로 보내라는 뜻이다.
- 공통 헤더: `X-Platform: PC_WEB`, `x-client-version: 1.0.2`, `X-Device-Id: <FingerprintJS visitorId>`.
  `X-Device-Id`가 세션 환경 판정에 쓰일 가능성이 있다.
- 검색: `POST /v1/market/web/items/searches/tool-tip`, JSON 본문. 본문 필드는
  `worldId, accountId, characterId, keyword, isExactMatch, page, limit(기본 20), sortType, filters, saveRecentKeyword`.
  응답에는 `searchKey`와 툴팁이 포함된 아이템 목록이 온다. 다음 페이지는
  `GET /v1/market/web/items/searches/{searchKey}/tool-tip`. 검색 1회마다 하루 한도가 1 줄어든다.
- 정렬: `sortType` 값 중 `PRICE_PER_ITEM_ASC` (개당 가격 낮은 순)이 기본이다.
- 필터 객체(`filters`)의 관련 키:
  - `itemCategory`: 기본 `["armor","armor::all"]`
  - `enhancementOption::potentialGrade`: `all|none|rare|epic|unique|legendary`
  - `enhancementOption::potentialFilters::isAddAll`: `true`면 "합산" 모드
  - `enhancementOption::potentialFilters::optionRows`: `[{ value: <옵션코드>, min: "<최소값>" }, ...]`
  - 에디셔널은 `additionalPotentialFilters::*`, 등급은 `additionalPotentialGrade`
  - `enhancementOption::starforceMin/Max`, `price::min/max`
  - 서버로 보낼 때 앱은 이 키들을 `enhancementOption.potentialOptionSum` (합산) 또는
    `enhancementOption.potentialOptions` 형태로 변환한다. 구현 시 실제 요청 본문을 캡처해 맞춘다.
- 옵션 코드 예: `skillCooldownReduction` (스킬 재사용 대기시간 감소), `strPercent` (STR %증가),
  `allStatsPercent`, `criticalDamagePercent`, `bossDamagePercent` 등. 전체 라벨↔코드 표는 번들의
  옵션 목록에서 그대로 가져온다.
- 하루 한도: `GET /v1/market/web/daily-limit` → `search.remaining`.
- 연속 검색 제한: 5초 안에 다시 검색할 수 없다.
- 월드/캐릭터: 검색은 월드 단위이며 계정의 캐릭터 하나를 골라야 한다. 1그룹(스카니아, 베라, 루나,
  제니스, 크로아, 유니온, 엘리시움, 이노시스, 레드, 오로라, 아케인, 노바, 챌린저스 1~3)과 2그룹(에오스,
  헬리오스, 챌린저스4)은 서로 거래가 안 된다. 계정/월드/캐릭터 목록 엔드포인트(`/v1/accounts` 등)는
  구현 시 확인한다.
- 접근 제한: 일반 HTTP 클라이언트로 페이지를 요청하면 403 차단 페이지가 온다. 브라우저에서는 열린다.
  한국 IP가 필요할 수 있다. 이 PC는 한국 IP다.

### 4.2 카카오톡 "나에게 보내기" (공식 문서로 확인)

- 엔드포인트: `POST https://kapi.kakao.com/v2/api/talk/memo/default/send`,
  헤더 `Authorization: Bearer <access_token>`, 본문 `template_object=<JSON>` (form-urlencoded).
- 필요한 앱 설정: 카카오 로그인 사용 설정, 리다이렉트 URI 등록, 동의항목에 `talk_message`.
  나에게 보내기는 별도 심사가 필요 없다.
- 토큰: access token 유효 6시간, refresh token 약 2개월. 프로그램이 refresh token으로 자동 갱신한다.
- 메시지 길이: text 템플릿의 `text`는 최대 200자. feed/list 템플릿은 글자 수 대신 줄 수 제한이라
  상세를 담기 어렵다. 그래서 text 템플릿을 쓰고, 아이템 1건당 메시지 1개로 보낸다.

### 4.3 실행 환경

- 프로그램은 사용자의 회사 Windows PC에서 돈다. 사용자가 로그인 창(넥슨 OTP, 카카오 동의)을 그 PC
  화면에서 직접 본다. Node.js LTS와 Playwright Chromium을 그 PC에 설치한다.
- 개발과 단위 테스트는 이 리눅스 PC(이 저장소)에서 한다. 따라서 코드는 Windows와 리눅스 양쪽에서
  돌아야 한다. 경로는 `path` 모듈로만 다루고, `.env`는 CRLF여도 읽히게 하고, npm 스크립트는
  PowerShell에서도 되는 형태로만 쓴다(셸 전용 문법 금지).
- 브라우저 창은 근무 시간 내내 떠 있고 최소화해 둔다. 사용자가 이를 허용했다. headless로 숨기지 않는다.
  로그인할 때와 평소의 브라우저 지문을 같게 유지해 "다른 환경" 판정을 피하기 위해서다.
- 근무 시간에만 켜고 퇴근 시 끈다. 하루 9시간 기준 15분 간격이면 약 36회 검색으로 한도 안에 든다.
- 아직 확인되지 않은 것: Playwright Chromium이 옥션의 403 차단을 통과하는지, 넥슨 로그인이 자동화
  브라우저에서 막히지 않는지. 구현의 0단계에서 Windows PC에서 먼저 확인한다(9절 참고).

## 5. 동작 방식

### 5.1 하루 흐름

1. 사용자가 터미널에서 프로그램을 켠다.
2. 프로그램이 저장된 브라우저 프로필로 브라우저 창을 띄우고 옥션 페이지를 연다. 세션이 살아 있으면
   창을 최소화하고 그대로 진행한다.
3. 세션이 없거나 끊겨 있으면 창을 앞으로 가져오고 "로그인하세요"라고 터미널에 안내한다.
   사용자가 넥슨 로그인과 OTP를 직접 끝내면 프로그램이 이를 감지해 창을 최소화하고 진행한다.
4. 시작하면 카카오톡으로 "감시 시작" 메시지를 1건 보낸다. 조건 요약과 오늘 남은 검색 횟수를 담는다.
5. 시작 직후 바로 1번 검색하고, 그 뒤 주기마다(기본 15분) 검색한다. 상위 N건이 이전과 다르면
   카카오톡으로 보낸다.
6. 사용자가 터미널에서 프로그램을 끈다(Ctrl+C). 브라우저도 함께 닫힌다.

### 5.2 검색 한 번의 절차

1. 남은 검색 횟수를 조회한다. 남은 횟수가 `MIN_REMAINING_SEARCHES`(기본 10) 이하이면 검색하지 않고,
   그 날 처음일 때만 "한도 임박, 검색 중단" 메시지를 보낸다. 다음 날 한도가 돌아오면 자동 재개한다.
2. `.env` 조건으로 검색 요청을 보낸다. 정렬은 개당 가격 낮은 순, 1페이지만 가져온다.
3. 결과에서 상위 N건을 뽑아 "지문"을 만든다. 지문은 각 매물의 고유 식별자와 개당 가격의 순서 있는
   목록이다. 고유 식별자가 응답에 없으면 툴팁 내용의 해시를 대신 쓰되, 남은 판매 시간처럼 매번 바뀌는
   값은 해시에서 뺀다.
4. 지문이 마지막으로 보낸 지문과 다르면 알림을 보내고 지문을 저장한다. 같으면 아무것도 하지 않는다.
5. 결과가 0건이고 직전에는 있었다면 "조건에 맞는 매물 없음" 메시지를 1건 보낸다.

지문은 `./data/state.json`에 저장한다. 프로그램을 껐다 켜도 결과가 같으면 다시 보내지 않는다.

### 5.3 알림 메시지

- 상위 N건이 바뀌면 바뀐 건만이 아니라 N건 전체를 다시 보낸다. 메시지는 매물 1건당 1개, 각 200자 이하.
- 각 메시지의 내용 순서와 우선순위:
  1. 순번과 개당 가격 (예: `[1/3] 1,234,567,890 메소`)
  2. 아이템명
  3. 잠재등급과 잠재능력 3줄
  4. 에디셔널 등급과 3줄
  5. 스타포스, 남은 업그레이드 횟수(업횟)
  6. 그 밖의 툴팁 정보
- 200자를 넘기면 뒤쪽 항목부터 잘라낸다. 가격, 이름, 잠재능력은 항상 들어간다.
- 메시지의 링크는 옥션 구매 페이지로 둔다.
- 알림 종류: 감시 시작, 매물 변경(최대 N개), 매물 없음, 세션 끊김(로그인 필요), 한도 임박, 연속 오류.

### 5.4 세션과 오류 처리

- 검색이나 한도 조회가 401/426으로 실패하면 먼저 페이지를 새로고침해 웹 토큰 세션을 다시 만들어 본다.
  그래도 안 되면 세션이 끊긴 것으로 보고 카카오톡으로 "로그인이 필요합니다"를 보낸 뒤, 브라우저 창을
  앞으로 가져와 로그인될 때까지 기다린다. 로그인되면 주기를 이어 간다.
- 프로그램이 오류로 비정상 종료될 때는 가능하면 카카오톡으로 "감시 중단" 메시지를 보내고 끝낸다.
- 네트워크 오류 등 그 외 실패는 다음 주기에 다시 시도한다. 3번 연속 실패하면 카카오톡으로 1번 알린다.
- 카카오 토큰 갱신에 실패하면 카카오톡으로는 알릴 수 없으므로 터미널에 눈에 띄게 출력하고 계속 검색은
  이어 간다.
- 검색 간 5초 제한은 주기가 15분이라 걸릴 일이 없지만, 수동 실행 명령에서는 지킨다.

## 6. 설정 (`.env`)

```
# 검색 조건
ITEM_NAME=에테르넬 나이트헬름
ITEM_EXACT_MATCH=true
POTENTIAL_GRADE=레전드리                  # 전체|없음|레어|에픽|유니크|레전드리
POTENTIAL_SUM=true                        # 잠재능력 "합산" 토글
POTENTIAL_OPTIONS=스킬 재사용 대기시간 감소:2, STR %증가:9
ADDITIONAL_POTENTIAL_GRADE=전체
ADDITIONAL_POTENTIAL_SUM=false
ADDITIONAL_POTENTIAL_OPTIONS=
STARFORCE_MIN=
STARFORCE_MAX=
PRICE_MAX=                                # 비우면 제한 없음

# 계정 선택
WORLD_NAME=                               # 예: 스카니아. 비우면 계정에 월드가 하나일 때만 자동 선택
CHARACTER_NAME=                           # 비우면 해당 월드에 캐릭터가 하나일 때만 자동 선택

# 동작
INTERVAL_MINUTES=15
TOP_N=3
MIN_REMAINING_SEARCHES=10

# 카카오
KAKAO_REST_API_KEY=
KAKAO_REDIRECT_PORT=3131
```

- 옵션 이름은 옥션 화면에 보이는 한글 라벨 그대로 적는다. 프로그램이 번들에서 가져온 라벨↔코드 표로
  변환한다. 모르는 라벨이면 시작할 때 바로 오류를 내고 가능한 라벨 목록을 보여 준다.
- 숫자는 모두 "이상" 조건이다.
- `.env`가 잘못되면 검색을 시작하기 전에 멈춘다. 검색 한도를 낭비하지 않기 위해서다.

## 7. 명령

- `npm start`: 감시 시작.
- `npm run kakao:auth`: 최초 1회. 브라우저로 카카오 동의 화면을 열고, 리다이렉트를 로컬 포트에서 받아
  토큰을 `./data/kakao-token.json`에 저장한다.
- `npm run search:once`: 검색을 1번만 하고 결과와 만들어질 메시지를 터미널에 출력한다. 카카오톡은 보내지
  않는다. 조건을 맞춰 볼 때 쓴다. 검색 한도 1회를 쓴다.
- `npm run kakao:test`: 카카오톡으로 테스트 메시지 1건을 보낸다.
- README: Windows 기준 설치 순서를 적는다. Node.js LTS 설치, `npm install`, `npx playwright install chromium`,
  카카오 개발자 앱 만들기(카카오 로그인 켜기, 리다이렉트 URI `http://localhost:3131/oauth` 등록,
  동의항목 `talk_message`), `.env` 작성, `npm run kakao:auth`, `npm run search:once`, `npm start` 순서다.

## 8. 내가 정한 것 (사용자 확인 필요 없이 진행하되, 반대하면 바꿈)

- 언어와 도구: Node.js + TypeScript, 실행은 `tsx`로 빌드 없이. 브라우저 제어는 Playwright(Chromium).
  Windows와 리눅스에서 똑같이 동작하고 로그인 상태를 프로필로 보관하기 쉬워서 골랐다.
- 로그인 상태 보관: Playwright의 persistent context를 `./data/browser-profile`에 둔다.
  넥슨 쿠키는 이 프로필 안에만 있고 `.env`에는 들어가지 않는다.
- API 호출 방식: 옥션 페이지를 실제로 띄운 상태에서 그 페이지 안에서 `fetch`를 실행한다. 헤더
  (`X-Device-Id` 등)는 앱이 실제로 보낸 요청에서 캡처해 그대로 재사용한다. 앱과 다른 "환경"으로
  보여 세션이 끊기는 일을 피하기 위해서다. UI를 클릭해서 검색하는 방식은 느리고 깨지기 쉬워 쓰지 않는다.
- 브라우저는 항상 보이는 창으로 띄운다. 세션이 확인되면 최소화하고, 로그인이 필요할 때만 앞으로
  가져온다. 최소화와 복원은 Chromium의 CDP 창 제어로 한다. (사용자가 "최소화해 두면 괜찮다"고 확인함)
- 주기 실행은 프로세스 안의 타이머로 한다. cron이나 OS 스케줄러는 쓰지 않는다.
- 시작 메시지를 1건 보낸다. 프로그램이 제대로 돌고 있는지 확인하기 위해서다.
- 상태와 토큰 파일은 `./data/`에 두고 `.gitignore`에 넣는다.
- 보내는 아이템 상세 항목과 순서는 5.3에 적은 대로 한다.

## 9. 구현자에게 맡기는 것

- 0단계 검증: 본격 구현 전에 Windows PC에서 Playwright Chromium으로 (1) 옥션 페이지가 403 없이 열리고,
  (2) 넥슨 로그인과 OTP가 끝나며, (3) 창을 최소화한 상태에서 세션 API와 검색 API가 성공하는지 확인한다.
  셋 중 하나라도 실패하면 설계로 돌아와 대안(사용자의 실제 Chrome에 CDP로 붙기 등)을 정한다.
- 검색 응답의 실제 필드 이름, 매물 고유 식별자, 툴팁 구조. 실제 요청을 캡처해 확정한다.
- 계정/월드/캐릭터 목록을 가져오는 엔드포인트와 응답 형태.
- `filters` 객체가 서버로 갈 때의 정확한 변환 규칙(합산 모드 포함). 앱의 요청 본문을 캡처해 맞춘다.
- 로그인 완료를 감지하는 방법(세션 API 재시도 간격 등).
- 재시도 간격, 타임아웃 값.
- 모듈 나누기. 참고로 예상되는 조각: 설정 파싱, 넥슨 브라우저/세션, 넥슨 API, 필터 변환, 감시 루프와
  변경 감지, 카카오 인증, 카카오 전송, 메시지 포맷.
- 테스트: 필터 변환, 변경 감지, 메시지 포맷(200자 규칙)은 순수 함수로 만들어 단위 테스트한다.
  실제 넥슨/카카오 호출은 수동 명령으로 확인한다.

## 10. 알려진 위험

- 넥슨이 API나 `x-client-version`을 바꾸면 깨질 수 있다. 426이나 알 수 없는 응답은 숨기지 말고
  터미널과 카카오톡에 드러낸다.
- 같은 창과 프로필을 계속 써도 서버가 "다른 환경"으로 판정할 가능성이 남아 있다. 그 경우 5.4의 세션
  끊김 흐름으로 처리되므로 사용자는 알 수 있다.
- 자동화된 접근은 넥슨 이용약관에 걸릴 수 있다. 본인 계정으로, 사람이 직접 하는 것과 같은 횟수(하루
  100회 이내)만 요청한다.
- 한국 IP가 아닌 곳에서는 사이트 자체가 열리지 않을 수 있다.
